# 📡 Радар вакансий — версия на несколько человек (админский гайд)

Это вариант для вас как администратора: один центральный движок обслуживает
до 10-15 человек, каждый видит только свои вакансии, настраивается сам через
веб-форму. Ваша роль — один раз всё связать, дальше система работает сама.

Если вам нужен вариант **только под себя одного** — используйте `README.md`
и `.github/workflows/radar.yml` (там же, в этом проекте), они никуда не делись.

---

## Что у вас получится в итоге

```
Человек → открывает вашу ссылку-форму → заполняет профиль
        → жмёт Start в Telegram-боте
        → каждый день сам получает дайджест + видит вакансии в своей таблице
```

Вы как админ: один раз настраиваете бота, ключ OpenAI, форму — и всё.
Новых людей подключаете, просто отправляя им ссылку на форму.

---

## Шаг 1. Общие секреты (один раз, для всех пользователей сразу)

Все шаги — как в основном README.md, но теперь эти ключи **общие на всех**,
пользователи свои не заводят:

1. **Telegram-бот** через `@BotFather` → `TELEGRAM_BOT_TOKEN`.
   Запомните также **юзернейм** бота (без `@`) — понадобится в форме.
2. **OpenAI ключ** → `OPENAI_API_KEY`.
   Учитывайте: теперь платите вы за оценку вакансий всех подключённых людей.
   На 10-15 человек по паре десятков вакансий в день — это по-прежнему
   недорого (доллары, не десятки долларов), но раз в месяц стоит проверять
   расход на platform.openai.com.

## Шаг 2. Административная Google Таблица + служебный аккаунт

1. Создайте service account в Google Cloud (см. README.md, тот же процесс) →
   `GOOGLE_SERVICE_ACCOUNT_JSON`.
2. Создайте новую пустую Google Таблицу — **это ваша», только вы должны иметь
   к ней доступ. Скопируйте её ID из URL → `ADMIN_SHEET_ID`.
3. Дайте service account'у доступ **редактора** к этой таблице (Настройки
   доступа → вставить e-mail из `client_email` в JSON-ключе).

## Шаг 3. Форма регистрации

Подробно — в `signup/README.md`. Коротко: Google Apps Script (бесплатный
бэкенд без сервера) создаёт запись в вашей админ-таблице + личную таблицу
для каждого нового человека; статичная HTML-форма (можно разместить на
GitHub Pages) отправляет туда данные.

## Шаг 4. Секреты в GitHub

Repository → Settings → Secrets and variables → Actions:

| Секрет | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | из шага 1 |
| `OPENAI_API_KEY` | из шага 1 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | из шага 2, весь JSON-файл целиком |
| `ADMIN_SHEET_ID` | из шага 2 |

## Шаг 5. Включить workflow

В проекте уже есть `.github/workflows/multi_radar.yml` с двумя задачами:

- **link-telegram** — каждые 10 минут проверяет, не нажал ли кто-то Start
  в боте по ссылке из формы, и привязывает его аккаунт.
- **run-radar** — раз в сутки (08:00 по Москве, поправьте cron под себя)
  прогоняет полный пайплайн для всех активных пользователей разом.

Ничего дополнительно включать не нужно — GitHub Actions подхватит workflow
из `.github/workflows/` автоматически после того, как вы запушите проект
в репозиторий.

## Шаг 6. Подключение людей

Просто отправьте им ссылку на форму (шаг 3). Дальше для каждого:
1. Заполняет форму → получает ссылку на личную таблицу + ссылку на бота.
2. Жмёт Start в Telegram.
3. На следующий день (или сразу, если запустите `run-radar` вручную через
   вкладку Actions → workflow_dispatch) начинает получать дайджест.

## Как проверить, что всё работает

1. GitHub → Actions → `Радар вакансий (много пользователей)` → Run workflow
   (вручную, не дожидаясь расписания) — это запустит сразу обе задачи.
2. Смотрите логи: `link_telegram.py` покажет, кого привязал; `multi_run.py`
   покажет по каждому пользователю, сколько вакансий собрано и отправлено.
3. Загляните в лист `Users` вашей админ-таблицы — там видно статус каждого
   (`telegram_chat_id` заполнен = привязан, `personal_sheet_id` = создана
   личная таблица).

## Управление пользователями

Всё редактируется прямо в листе `Users` вашей админ-таблицы:
- поставить `status = paused` — временно отключить человека (дайджест
  перестанет приходить, данные не удаляются);
- поменять `channels`, `hh_companies`, `hh_titles`, `candidate_summary` —
  правится прямо в ячейке, подхватится со следующего запуска;
- удалить строку — полностью убрать человека из системы (личную таблицу
  придётся удалить отдельно вручную в Google Drive, если нужно).

## Ограничения текущей версии (честно)

- Скоринг-рубрика и пороги — общие на всех пользователей (не настраиваются
  индивидуально через форму). Если кому-то нужна другая строгость — правьте
  `DEFAULT_SCORING_RUBRIC` / `DEFAULT_THRESHOLDS` в `multi_run.py` вручную.
- Карьерные сайты компаний (`fetch_careers.py`) в мультипользовательском
  режиме пока не подключены — там всё равно нужен парсер под каждую
  конкретную компанию, это скорее общий источник на всех, а не персональный.
- Ошибка у одного пользователя (например, недоступна его личная таблица)
  не должна ронять прогон остальных — `multi_run.py` перехватывает ошибки
  по каждому пользователю отдельно и продолжает со следующим.
